# 图级批次合并 (Block-Diagonal Batching) 实施计划

> 版本: v5 (终版) | 日期: 2026-05-28 | 目标文件: `GAT_V2026.py`, `config.py`

---

## 一、背景与动机

当前训练配置为 `batch_size=1, grad_accum=8`，每个 mini-batch 只处理一个 GNSS 历元（平均 ~14 个节点、~100 条边），GPU 利用率极低（< 5%）。每个 epoch 耗时 ~1.4 分钟（berlin1），四个数据集串行跑完 100 epoch 需要 ~2 天。

**目标**: 通过 block-diagonal batching 将多个历元的独立小图拼接为一个大图送入 GPU，单次前向处理 32 个图，预期加速 5-10 倍。

## 二、约束与假设

- **所有改动集中在 `GAT_V2026.py` 和 `config.py`**，`GAT_V2025.py` 保持不动作为基线备份
- 向量化 GATLayer 必须通过单元测试才能推进后续步骤
- 新增 `USE_BLOCK_DIAGONAL = True` 开关，设为 `False` 即可一键回退到旧行为
- 有效 batch 从 8→32（4×），LR 从 1e-4 降至 5e-5 作为保守起点

## 三、实测依据

| 数据集 | 每图节点 | 每图边数 | batch_32 边数（均值） | batch_32 边数（最坏） |
|--------|---------|---------|---------------------|---------------------|
| berlin1_potsdamer_platz | 14.7 ± 2.0 | 100 ± 23 | 3,189 | 4,160 |
| berlin2_gendarmenmarkt | 15.2 ± 0.9 | 95 ± 12 | 3,037 | 3,840 |
| frankfurt1_maintower | 12.6 ± 1.5 | 69 ± 16 | 2,209 | 3,520 |
| frankfurt2_westendtower | 15.4 ± 0.7 | 108 ± 12 | 3,441 | 4,032 |

结论: batch_32 内存 < 10 MB，瓶颈不在显存，在 Python for-loop 遍历边。

## 四、实施步骤

### Step 0: 向量化 GATLayer.forward

**当前代码存在的问题**: `GATLayer.forward` 使用 Python 双循环遍历边和注意力头：
```python
for i in range(edge_index.size(1)):           # O(E) ~ 100-3000 次
    for head_idx in range(h):                  # O(H) = 8 次
        w = att_weight[head_idx].item()        # .item() 触发 CPU-GPU 同步
        out[dst, head_idx, :] += w * x_hat[src, head_idx, :]
```
batch_size=1 时 ~100 边 × 8 头 = 800 次迭代，尚可接受。batch_size=32 时 ~3200 边 × 8 头 = 25,600 次 `.item()` 调用，会严重拖慢训练。

**向量化版本**:
```python
att_weight = F.softmax(self.att.view(-1), dim=0)  # (2*out_dim,) = (256,)

src = edge_index[0].long()   # (E,)  -- 所有边的源节点索引
dst = edge_index[1].long()   # (E,)  -- 所有边的目标节点索引

# 过滤越界索引（与原代码的 if src>=N or dst>=N: continue 精确保留语义）
mask = (src < N) & (dst < N)
src, dst = src[mask], dst[mask]

out = torch.zeros(N, h, out_dim, device=x.device, dtype=x.dtype)
for head_idx in range(h):
    # 维度追踪:
    #   x_hat:             (N, H, D)
    #   x_hat[src, h, :]:  (E, D)  -- 按源节点索引取特征
    #   att_weight[h]:     ()       -- 标量权重
    #   msgs:              (E, D)  -- 广播: (E,D) * ()
    msgs = x_hat[src, head_idx, :] * att_weight[head_idx]
    # out[:, h, :] 是 (N, D) view，stride[0] = H*D（连续张量的跨步切片）
    # index_add_(0, dst, msgs): 沿 dim=0，
    #   将 msgs[i, :] 累加到 out[dst[i], h, :] —— 与原代码语义完全等价
    out[:, head_idx, :].index_add_(0, dst, msgs)
```

**前置单元测试（门控条件，不通过则回退到半向量化版本）**:

```python
import torch
# 取一个真实历元的数据
nf, ei, ea, pe, lb = dataset[0]  # 来自 berlin1

# 创建旧/新 GATLayer（相同初始化）
old_layer = GATLayer(in_features=128, out_features=128, heads=8, concat=False)
new_layer = GATLayerV2(in_features=128, out_features=128, heads=8, concat=False)
new_layer.load_state_dict(old_layer.state_dict())

# 前向输出比对
old_out = old_layer(nf, ei)
new_out = new_layer(nf, ei)

# 双重确认 shape 一致
assert old_out.shape == new_out.shape, \
    f"Shape mismatch: {old_out.shape} vs {new_out.shape}"

max_diff = (old_out - new_out).abs().max().item()
assert max_diff < 1e-6, \
    f"Forward mismatch: max_diff = {max_diff:.2e}"

# 反向梯度比对
old_out.sum().backward()
new_out.sum().backward()
for (n_o, p_o), (n_n, p_n) in zip(
    old_layer.named_parameters(), new_layer.named_parameters()
):
    grad_diff = (p_o.grad - p_n.grad).abs().max().item()
    assert grad_diff < 1e-5, \
        f"Gradient mismatch in '{n_o}': diff = {grad_diff:.2e}"

print("Step 0 PASSED: forward & backward match exactly")
```

**兜底方案**: 若向量化版本不一致，退回到仅消除 `.item()` 和 `int()` 的半向量化版本：
```python
for i in range(edge_index.size(1)):
    src, dst = edge_index[0, i].item(), edge_index[1, i].item()
    if src >= N or dst >= N:
        continue
    for head_idx in range(h):
        out[dst, head_idx, :] += x_hat[src, head_idx, :] * att_weight[head_idx]
```

### Step 1: 编写 `batch_collate_fn`

**原理**: K 个独立小图的邻接矩阵按对角线分块拼接。不同图之间无边相连，GAT 消息传递天然隔离。

```python
def batch_collate_fn(batch):
    """
    将 K 个独立 GNSS 图拼接为 block-diagonal 大图。

    Input: list of K tuples, 每个 tuple 包含:
        (node_features (N_i, 11), edge_index (2, E_i), edge_attr (E_i,),
         pseudorange_error (N_i,), nlos_label (N_i,))

    Output: tuple of 5 batched tensors:
        node_features      (N_total, 11)
        edge_index         (2, E_total)  -- 每个子图的节点索引已偏移
        edge_attr          (E_total,)    -- edge_attr 当前未使用，cat 备用
        pseudorange_error  (N_total,)
        nlos_label         (N_total,)
    """
    nfs, eis, eas, pes, lbs = [], [], [], [], []
    offset = 0  # 累积节点偏移量

    for nf, ei, ea, pe, lb in batch:
        N = nf.size(0)  # 当前图的节点数
        if N == 0:      # 防御空图（Dataset 已过滤，但保留检查）
            continue

        nfs.append(nf)
        eis.append(ei + offset)  # 节点索引偏移——关键步骤
        eas.append(ea)           # edge_attr 无需偏移（当前未使用）
        pes.append(pe)
        lbs.append(lb)
        offset += N

    # 防御：极端情况下全空
    if len(nfs) == 0:
        return (
            torch.zeros(0, 11),
            torch.zeros(2, 0, dtype=torch.long),
            torch.zeros(0),
            torch.zeros(0),
            torch.zeros(0),
        )

    return (
        torch.cat(nfs, dim=0),   # (N_total, 11)
        torch.cat(eis, dim=1),   # (2, E_total)
        torch.cat(eas, dim=0),   # (E_total,)
        torch.cat(pes, dim=0),   # (N_total,)
        torch.cat(lbs, dim=0),   # (N_total,)
    )
```

### Step 2: 修改 DataLoader 创建

在 `GAT_V2026.py` 的 `main()` 函数中，将原有的 `batch_size=1, collate_fn=lambda x: x[0]` 替换为条件分支：

```python
if config.USE_BLOCK_DIAGONAL:
    # 新: block-diagonal batching
    train_loader = DataLoader(
        train_dataset,
        batch_size=32,
        shuffle=True,
        num_workers=8,
        pin_memory=True,
        collate_fn=batch_collate_fn,
        drop_last=False,
    )
    val_loader = DataLoader(
        val_dataset,
        batch_size=64,          # 验证集可用更大 batch（无梯度）
        shuffle=False,
        num_workers=4,
        pin_memory=True,
        collate_fn=batch_collate_fn,
        drop_last=False,
    )
else:

    train_loader = DataLoader(
        train_dataset,
        batch_size=1,
        shuffle=True,
        num_workers=0,
        collate_fn=lambda x: x[0],
    )
    val_loader = DataLoader(
        val_dataset,
        batch_size=1,
        shuffle=False,
        num_workers=0,
        collate_fn=lambda x: x[0],
    )
```

### Step 3: 清理 squeeze hack

旧 batching 的 `lambda x: x[0]` 会把 tuple 拆成单图，但 PyTorch DataLoader 的默认 collate 会在外层再包一个 batch 维度，导致 `node_features.dim() == 3`。因此旧代码在 `train_epoch` 和 `evaluate` 中各有一段 squeeze 逻辑。新 batching 不再需要。

**在 `train_epoch` 函数中删除以下 4 行**:
```python
# 删除开始
if node_features.dim() == 3 and node_features.size(0) == 1:
    node_features = node_features.squeeze(0)
if edge_index.dim() == 3 and edge_index.size(0) == 1:
    edge_index = edge_index.squeeze(0)
# 删除结束
```

**在 `evaluate` 函数中删除同样 4 行**。

```python
# ============================================================

```

**LR 回退策略**: 层二验证时若出现训练不稳定，按以下顺序尝试：

| 触发条件 | 动作 | 原理 |
|---------|------|------|
| epoch 5 时 Val Loss > 旧版同 epoch Val Loss × 1.2 | LR 升至 8e-5，重置 optimizer momentum | 4× batch 可能不需要降 LR 这么多 |
| epoch 5 时 Val Loss 相邻 epoch 间差值 > 0.05（震荡） | LR 降至 3e-5 | 梯度估计更精确但步长过大 |
| epoch 10 时 Val Acc < 旧版同 epoch Acc − 0.03 | BATCH_SIZE 降至 16, LR 回 5e-5 | 有效 batch 过大导致收敛变慢 |
| 出现 NaN loss | BATCH_SIZE 降至 16, LR 降至 3e-5, 关闭 AMP | 排除 AMP 与大 batch 的交互问题 |

### Step 5: 梯度累积余数处理

新配置下 `GRADIENT_ACCUMULATION = 1`，`(batch_idx + 1) % 1 == 0` 恒成立，每个 batch 都触发 `optimizer.step()`。`train_epoch` 末尾处理未满 grad_accum 的余数分支：

```python
if (batch_idx + 1) % gradient_accumulation != 0 and num_batches > 0:
```

在 `grad_accum = 1` 时此条件永不满足，逻辑自行消失，无需修改代码。

### Step 6: 验证计划

验证分三层递进，每一层都有硬性通过标准。

#### 层一: 前向一致性验证（白盒）

**目的**: 确认 `batch_collate_fn` + 向量化 GATLayer 在不同 batch_size 下输出完全一致。

**步骤**:
1. 取 berlin1 验证集的前 20 个 epoch（覆盖不同节点数的图）
2. 分别以 `batch_size=1` 和 `batch_size=5` 运行 `evaluate()`
3. 逐节点比较 p_los 和 log_sigma

**判定标准**:
- 每个节点的 p_los 差异 < 1e-6（`torch.allclose(atol=1e-6)`）
- 每个节点的 log_sigma 差异 < 1e-6
- Val Accuracy / F1 / Loss 完全相同（FP 误差 < 1e-12）

**不通过时的处理**: 回退到 Step 0-bis（半向量化 GATLayer），重跑层一。

#### 层二: 训练收敛对比（10 epochs, berlin1）

**目的**: 确认新 batching 下的训练动态与旧版本一致。

**步骤**:
1. 新旧版本各从零开始训练 10 epoch，分别记录 TensorBoard 日志
2. 对比 Val Accuracy、F1、Loss 三条曲线

**判定标准**:
- epoch 10 时新版本 Val Acc ≥ 旧版本 Val Acc − 0.02
- epoch 10 时新版本 Val F1 ≥ 旧版本 Val F1 − 0.02
- **大 batch 正则化效应的特殊说明**: 若新版本 Val F1 比旧版本低 0.015~0.025，但曲线趋势一致且无震荡，可判定为通过。原因是 32× 更大的 batch 天然引入更强正则化，峰值略低但泛化方差更小，属正常现象。
- 无 NaN、无 loss 爆炸

**不通过时的处理**: 按 Step 4 的 LR 回退表依次尝试，每次重跑层二。

#### 层三: 速度基准

**目的**: 量化加速效果。

**步骤**:
1. 测量新旧版本在 berlin1 上各 3 个 epoch 的平均耗时（跳过第一个 epoch 的 warmup）
2. 计算加速比

**判定标准**:
- 旧版本: ~1.4 min/epoch
- 新版本: ≤ 0.3 min/epoch
- 加速比 ≥ 4.6× 即通过

## 五、不变的部分

以下代码**无需修改**，其行为与 batching 无关：

- **`NLOSGAT.forward`**: 只依赖 `x.size(0)` 和 `edge_index`。block-diagonal 邻接中不同子图之间无边相连，GAT 消息传递天然隔离。
- **`NLOSLoss.forward`**: 所有 `.mean()` 操作在全部节点上计算，不关心 batch 边界。
- **`evaluate`**: 收集所有节点的预测到列表，最后统一计算指标，与 batching 无关，输出确定性相同。
- **`_extract_elevation`**: 逐节点操作，不受 batching 影响。
- **Checkpoint 保存/加载**: 只存模型参数和优化器状态，与 batch_size 无关。
- **`edge_attr`**: 当前 `model.forward` 不接收 edge_attr，它是被加载到 GPU 但未使用的死数据。`batch_collate_fn` 中采用 `torch.cat(eas, dim=0)`（无需 offset），将来启用时 collate 结构已正确。
- **`att_weight` 的 bug**: `self.att` 维度为 `(1, 2*out_features) = (1, 256)`，softmax 后只使用前 8 个元素（对应 8 个 head），剩余 248 个参数白训练。本次精确保留此行为——向量化版本使用 `att_weight[head_idx]` 取前 8 个值，与原代码完全一致。修复留到后续的 MoG 混合高斯阶段。

## 七、风险与应对矩阵

| 风险 | 概率 | 严重度 | 应对措施 |
|------|------|--------|---------|
| 向量化 GATLayer 输出与原始不一致 | 中 | 高 | 层一门控: 逐节点比对 < 1e-6；不通过则退到半向量化 |
| `index_add_` 在 non-contiguous view 上的行为异常 | 低 | 高 | 单元测试双重确认 shape + forward/backward 全等 |
| batch_size=32 导致 loss 不收敛 | 低 | 中 | LR 回退表: 3e-5 / 8e-5 / BATCH_SIZE→16 |
| `num_workers=8` 在 Windows 上引发 multiprocessing 错误 | 低 | 低 | 降为 `num_workers=4`；`run_full_training.py` 已有 `if __name__ == '__main__'` 保护 |
| 大 batch 导致 Val F1 轻微下降 | 中 | 低 | 已明确为可接受的正常现象（大 batch 正则化），≤ 0.025 即通过 |
| 未满 batch 的边缘情况触发 NaN | 极低 | 低 | `batch_collate_fn` 内 `N==0` 防御 + 空 batch 占位符 |
