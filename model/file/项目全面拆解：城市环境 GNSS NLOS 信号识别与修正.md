## 1. 项目总览：这个项目在解决什么问题？

### 先从生活场景说起

你在城市里用手机导航，走进一条高楼林立的街道，导航突然跳来跳去，定位误差几十上百米。这就是这个项目要解决的问题。

**为什么会这样？**

GPS（准确说是 GNSS）定位的原理很简单：你的设备同时接收多颗卫星发来的信号，每颗卫星报告"我在哪里，信号在几点几秒发出"，你的设备根据信号传播时间 × 光速 = 距离，用多颗卫星的距离联立方程解出自己的位置。

```
卫星 A ──────────────────→ 你的设备
  （已知位置，测出距离）
卫星 B ──────────────────→ 你的设备
卫星 C ──────────────────→ 你的设备
三个球的交点 = 你在哪里
```

但在城市里，信号会被楼房挡住，然后绕路反射过来：

```
卫星 A ──────→ 楼顶 ──弹射→ 你的设备
              （走了更长的路）
```

这叫 **NLOS（Non-Line-of-Sight，非视距）**。信号绕路走了，传播时间变长，测出的"距离"偏大，于是方程解出的位置就偏了。偏差通常在几十米到几百米量级。

### 项目要交付什么？

一个三层的自动化系统，输入原始 GNSS 信号观测数据，输出修正后的高精度位置估计。具体说：

- **输入**：每个时刻（历元）所有可见卫星的原始测量值（伪距、信号强度、仰角等）
- **输出**：该时刻接收机的位置坐标（经纬度/ECEF），比传统方法精度提升 2-11%

项目在柏林和法兰克福的城市数据集上验证，最终比纯传统方法（Standard LS）在全部 4 个场景都有改善。

## 2. 模块划分：三个模块各管什么？

项目叫 **PI-PEM（Physics-Informed Probabilistic Error Modeling）**，分三个模块：

```
原始 GNSS 数据
      │
      ▼
┌─────────────────────────────────────┐
│ Module 1: NLOS 感知模块 (part1_GAT) │
│ "每颗卫星是 LOS 还是 NLOS？         │
│  如果是 NLOS，误差大概多少？"        │
└───────────────────┬─────────────────┘
                    │ p_los, mu_nlos, sigma_los, sigma_nlos
                    ▼
┌─────────────────────────────────────┐
│ Module 2: 融合定位模块 (part2_FG)   │
│ "用 Module 1 的软信息，             │
│  算出最优位置估计"                   │
└───────────────────┬─────────────────┘
                    │ 位置估计 + 残差
                    ▼
┌─────────────────────────────────────┐
│ Module 3: 残差反馈模块 (part3_RFB)  │
│ "Module 2 的策略在当前场景有没有用？ │
│  动态决定用哪个方法"                 │
└───────────────────┬─────────────────┘
                    │
                    ▼
             最终位置输出
```

用一个类比来说：

- **Module 1** 像一个"卫星体检医生"，给每颗卫星打分："这颗卫星信号可信度 80%，偏差预计 200 米"
- **Module 2** 像一个"统计学家"，拿着体检报告算：如果这些分数是准的，最优解在哪里？
- **Module 3** 像一个"项目经理"，观察统计学家的工作效果，发现他在某些场景反而帮倒忙，就切换策略

## 3. 模块详解

### Module 1：NLOS 感知（Graph Attention Network + Mixture of Gaussians）

#### 输入是什么？

每个历元（时刻）的所有可见卫星，每颗卫星提供 **11 维特征**：

| 特征         | 含义                         | 直觉           |
| ---------- | -------------------------- | ------------ |
| 仰角         | 卫星在天空中多高                   | 越低越容易被楼遮住    |
| 方位角        | 卫星在哪个方向                    | 朝建筑物方向的卫星更危险 |
| CNO（载噪比）   | 信号强度                       | NLOS 信号通常更弱  |
| 伪距标准差      | 接收机自报的测量不确定度               | 不稳定说明信号可疑    |
| 伪距创新量      | 测量值与预测值之差                  | 差异大说明有偏差     |
| cos(仰角)    | 几何辅助特征                     |              |
| 星座 one-hot | GPS/Glonass/Galileo/BeiDou | 不同系统特性不同     |

#### 网络结构：为什么用图（Graph）？

在某个时刻，你能看到 8-20 颗卫星。普通神经网络（MLP）会独立处理每颗卫星，但这个项目用了 **图注意力网络（GAT）**——把卫星之间的关系也考虑进去。

**为什么卫星之间有关系？**

想象你站在路口，北边有一栋大楼。北边方向的卫星可能都被遮住了——它们有共同的命运，应该互相"借鉴"信息。

```
卫星群（节点 = 卫星，边 = 方位角相近的卫星对）
     卫星A(北45°) ←——→ 卫星B(北80°)  ← 可能都被同一栋楼遮
     卫星C(南30°) ←——→ 卫星D(南60°)  ← 可能都能直视
```

GAT 让每颗卫星"问问邻居"自己状态怎样，然后综合判断。

**注意力机制**就像开会投票：卫星 A 在判断自己是否 NLOS 时，会给方位角相近的卫星 B 更高的参考权重，给方位角相差很远的卫星 C 低权重。

#### 输出是什么？

对每颗卫星输出 **4 个数**（混合高斯模型参数）：

```python
p_los     # 这颗卫星是 LOS 的概率，范围 [0, 1]
mu_nlos   # 如果是 NLOS，伪距偏差的均值（期望多偏多少米）
sigma_los # LOS 情况下的测量误差标准差
sigma_nlos# NLOS 情况下的测量误差标准差
```

**用概率而不是用"是/否"的好处是什么？**

硬分类："这颗卫星是 NLOS" → 要么用要么不用，信息损失大。

软概率："这颗卫星 70% 可能是 NLOS" → 可以"打折"使用，信息保留更多。

用数学表达：伪距误差的概率分布是两个高斯的混合：

```
P(误差) = p_los × N(0, σ_los)           ← LOS 分量：误差小，均值为0
        + (1-p_los) × N(μ_nlos, σ_nlos)  ← NLOS 分量：误差大，有正向偏移
```

这就是"混合高斯（Mixture of Gaussians）"。

#### 训练过程发生了什么？（简述版本演变）

这个模型经历了 8 个版本的迭代修复，最关键的两个问题：

**问题一（v1-v4）：`mu_nlos` 方向反了**

训练完发现：`mu_nlos` 在 LOS 卫星上的值（248-465m）**大于** NLOS 卫星（162-395m）——逻辑完全颠倒。

原因是模型找到了一个"投机取巧"的方法：把 LOS 的 `mu` 推高，可以让损失函数数值更好看，但违背了物理含义。

**修复（v8）**：加了一个"对比排序损失"——明确告诉模型："不管其他怎样，NLOS 的 mu 必须大于 LOS 的 mu"：

```
ranking_loss = max(0, 0.15 - (mean_μ_NLOS - mean_μ_LOS))
```

如果 NLOS 的均值没有比 LOS 大 150m，就受到惩罚。

### Module 2：因子图融合定位

#### 背景：传统定位怎么做？

最简单的定位叫**最小二乘（LS）**：

```
你有 n 颗卫星，每颗给你一个方程：
  测量距离_i = 真实距离(位置, 卫星i位置) + 接收机钟差

n 个方程，4 个未知数（x, y, z, 钟差），用最小二乘解
```

**加权最小二乘（WLS）**：认为不同卫星的测量质量不同，给高质量卫星更大权重。

#### Module 2 的想法

既然 Module 1 给了每颗卫星一个"误差分布"，为什么不把这个分布直接用到定位里？

```
最大化：所有卫星观测同时成立的概率
= 对数似然求和
= argmax_位置 Σ log P(测量残差_i | 位置)

其中 P(残差_i | 位置) 就是 Module 1 输出的混合高斯分布
```

这叫**因子图优化（Factor Graph Optimization）**。用 `scipy` 的 `L-BFGS-B` 优化器来数值求解。

#### Module 2 的惨痛教训（v3-v8 的失败历史）

整个 Module 2 花了 6 个版本都没让所有数据集超越 Standard LS（传统方法），只有 frankfurt1 有效（+9.2%），其他三个场景反而变差。

**为什么加权反而变差？——DOP 膨胀问题**

GNSS 定位有一个概念叫 **DOP（Dilution of Precision，精度衰减因子）**，本质是卫星几何分布的质量指标。

想象用三角测量定位：

- 如果三个测量站分布在三个不同方向 → 三角稳定，定位精度高（DOP 小）
- 如果三个测量站都在同一方向 → 三角退化，定位精度差（DOP 大）

当我们把 NLOS 卫星的权重降低时，相当于"假装某些卫星不存在"。如果这些 NLOS 卫星恰好是几何上不可缺少的，降权后 DOP 增大，定位精度反而下降。

```
降权 NLOS 卫星带来的精度提升
        vs
DOP 增大带来的精度下降

在 3/4 的场景：DOP 损失 > NLOS 修正收益
```

这就是为什么静态加权的 Module 2 在大多数场景无效。Frankfurt1 有效是因为那个场景的 NLOS 卫星恰好几何上是冗余的，可以降权而不损失 DOP。

### Module 3：残差反馈与自适应选择

#### 核心思路

既然 Module 2 的加权策略在有些场景有效、有些场景有害，那就**动态判断当前场景是哪种情况，自动切换方法**。

判断的依据是**残差（Residual）**：用 Module 2 的结果和 Standard LS 的结果相比较，看哪个更接近真值。

这叫**残差反馈（Residual Feedback）**。

#### 三个核心组件

**组件 A：残差创新跟踪器（ResidualInnovationTracker）**

维护一个最近 50 个历元的窗口，记录：

```
创新值 = Module2误差 - StandardLS误差
```

- 负值 → Module 2 比 LS 好（该场景适合加权）
- 正值 → Module 2 比 LS 差（该场景不适合加权）

**组件 B：场景质量检测器（SceneQualityDetector）**

用三个特征来预测当前历元用 Module 2 是否有益：

```python
score = 0.4 × (p_los_gap 够大)    # Module 1 的区分度
      + 0.4 × (加权不会膨胀 DOP)   # 几何约束
      + 0.2 × (NLOS 卫星几何冗余)  # 可以放心降权
```

**组件 C：自适应选择器（AdaptivePosCorrector）**

```python
if score >= 0.68:  # 高把握
    使用 FG-MoG+2A（完整因子图优化）
elif score >= 0.60:  # 中等把握
    使用 WLS-MoG（加权最小二乘）
else:  # 没把握
    使用 Standard LS（标准方法，最安全）

# 安全保险：如果选的方法比 LS 差 5% 以上，强制回退到 LS
if 选择的方法误差 > LS误差 × 1.05:
    使用 Standard LS
```

#### 一个重要的反直觉发现

实验中加了一个"后验校正（PosteriorPlosCorrector）"模块，想通过定位残差来修正 Module 1 的输出。听起来很合理，但消融实验（ablation study）发现它**反而有害**：

- 它修改了 `p_los` 值
- 修改后 `p_los` 区分度下降（LOS 和 NLOS 卫星的 `p_los` 值变得接近）
- 检测器认为场景质量变差 → FG 使用率从 45.7% 降到 1.9%
- Frankfurt1 的定位精度从 467m 退化到 522m

**结论：移除后验校正**，系统反而更好。这是研究中的一个真实发现，有科学意义。

## 4. 流程串联：数据如何在模块间流动？

以一次完整的定位为例，假设是一个城市里的某个历元，有 13 颗可见卫星：

```
步骤 1：数据读取
  ↓
读取 RXM-RAWX.csv（13 颗卫星的原始测量：伪距、CNO、仰角...）
读取 SP3 精密星历（每颗卫星在该时刻的精确位置）
读取 NAV-POSLLH.csv（地面真值 GPS 位置，仅用于训练/评估）
  ↓
步骤 2：特征工程（NodeFeature_Generate.py）
  ↓
将原始数据转换为 11 维特征矩阵（13 颗卫星 × 11 维）
构建图结构：方位角差 < 90° 的卫星之间连边
  ↓
步骤 3：Module 1 推理（GAT_V2025.py）
  ↓
图注意力网络处理，输出每颗卫星的：
  p_los:     [0.92, 0.15, 0.78, 0.21, ...]  ← 13 个值
  mu_nlos:   [0.10, 0.28, 0.12, 0.31, ...]  ← 13 个值（km）
  sigma_los: [0.05, 0.08, 0.06, 0.07, ...]  ← 13 个值（km）
  sigma_nlos:[0.12, 0.35, 0.14, 0.38, ...]  ← 13 个值（km）
  ↓
步骤 4：Module 2 定位（factor_graph_fusion.py）
  ↓
同时计算：
  - Standard LS：忽略所有软信息，用均匀权重解方程 → 位置 A
  - WLS-MoG：用 p_los/sigma² 作为权重 → 位置 B
  - FG-MoG：最大化混合高斯联合似然 → 位置 C
  ↓
步骤 5：Module 3 自适应选择（residual_feedback.py）
  ↓
检测器计算当前历元 score = 0.65（中等偏高）
跟踪器说最近 50 个历元 Module 2 平均误差比 LS 小 15m
→ 决定：使用 FG-MoG（位置 C）
→ 安全检查：位置 C 比 Standard LS 好 → 确认输出位置 C
  ↓
输出：最终位置坐标（经纬度）
```

## 5. 结果解读

### 最终数字

以 CEP50（50% 的历元定位误差低于此值，单位米）为主要指标：

|数据集|Standard LS（不用任何 AI）|Adaptive-M3 v4（最终系统）|改善|
|---|:-:|:-:|:-:|
|柏林 波茨坦广场|904.5m|**872.8m**|+3.5%|
|柏林 御林广场|610.8m|**598.5m**|+2.0%|
|法兰克福 美茵塔|525.2m|**467.4m**|+11.0%|
|法兰克福 西区塔|382.6m|**368.0m**|+3.8%|

### 这些数字意味着什么？

**成绩单：**

- 4/4 场景全部超越传统方法 ✅
- 法兰克福美茵塔：提升最显著，从 525m 到 467m，少了将近 60 米误差
- 安全保证：系统从未比传统方法更差（最坏情况保底）

**但要诚实说局限：**

- 改善幅度不大（2-11%），绝对误差仍在 350-900 米量级
- 这是纯伪距定位的天花板，没有引入惯导、载波相位等辅助信息
- Frankfurt2 后期存在间歇性退化（但安全回退机制避免了它破坏整体指标）

### 研究贡献的科学价值

从纯研究角度，这个项目有几个真实发现值得记录：

1. **DOP 膨胀是城市 WLS 定位的主要失败原因**——这是通过大量实验才总结出来的，有诊断证据
    
2. **后验校正（posterior correction）有害**——一个反直觉但经实验证明的结论，对后续研究有指导意义
    
3. **残差反馈使 AI 辅助定位具有"普适性"**——静态 Module 2 只在一个场景有效，加了 Module 3 后四个场景全有效，说明在线自适应是关键
    
4. **mu_nlos 方向性错误的修复方法**——通过对比排序损失解决了神经网络学到违背物理直觉输出的问题
